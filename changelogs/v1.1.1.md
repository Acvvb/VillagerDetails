## English

### 🚀 Version Overview
v1.1.1 is a maintenance and refactor release focused on async processing, thread-pool locking and lifecycle, config/IO lifecycle, villager trade global search, and fixes for auto trade refresh, Happy Ghast speed, and riding-state logout issues. The client/server config sync interface refactor preserves compatibility, and the new version handshake lays groundwork for a future version-compatibility framework. No additional intentional breaking changes beyond the 1.1.0 protocol baseline.

### ✨ New Features

#### 🎮 Game Rules
- Merged the Auto Villager Trade, 331, and Terracotta Refresh rules into the Auto Villager Trade rule; the trade index now supports enchanted books, terracotta, and 331.
- Auto Villager Trade now runs asynchronously and simulates vanilla random-tick refresh, no longer relying on the previous random-tick calculation and better matching vanilla refresh probabilities.

#### 🖥️ Client & Search
- Added global villager trade search, supporting multilingual search and custom search keywords via config. Specific-level enchanted books are not yet supported; only max-level enchanted books can be searched. Whether to support specific-level enchanted books is under evaluation.

#### 🔌 Protocol
- Added client/server version handshake communication, preparing to decouple a compatibility framework for client/server version differences.

#### 📚 Documentation
- Added and organized project development documentation, archiving the project framework and implementation details of each rule; see the documents under the `doc` directory.

### 🐛 Bug Fixes
- Fixed an issue where auto villager trade refresh could not refresh trades.
- Fixed an issue where Happy Ghast speed adjustments did not take effect immediately and required exiting and re-entering the riding state.
- Fixed an issue where logging out while riding on another player's head did not clear the riding state, causing the server to spam massive data-inconsistency check logs every tick.
- Fixed an issue where, after relogging from riding on another player's head, the riding player could not see the ridden player's model.

### ⚡ Architecture & Performance Optimizations

#### 🧵 Async & Thread Pools
- Moved query operations to asynchronous thread processing.
- Optimized thread-pool lock types, replacing broad blocking locks with optimistic locks.
- Changed thread pools to semi-blocking shutdown and stepped automatic expansion.
- Split the global thread pool; IO and business thread pools are now managed separately.

#### 📂 Config & IO
- Improved config naming.
- Refactored the config management lifecycle; forces a config write once on abnormal game exit.
- Refactored the IO write module and extracted it into a shared component.
- Refactored client/server config sync interfaces without affecting compatibility.

#### 🧹 Code Quality & Performance
- Cleaned up over-encapsulation and confusing code patterns.
- Removed some reflection injection that slowed startup.
- Optimized potential memory leaks on both server and client.

## 中文

### 🚀 版本定位
v1.1.1 为维护与重构版本，重点围绕异步处理、线程池锁类型与生命周期、配置/IO 生命周期、村民交易全局搜索，以及自动刷新交易、乐魂速度、骑行状态退出等问题的修复。客户端与服务端配置同步接口重构不影响兼容性，新增版本号握手通信为后续版本差异兼容性框架铺路。除 1.1.0 已建立的协议基线外，本版不主动引入额外破坏性变更。

### ✨ 新增功能

#### 🎮 游戏规则类
- 将自动村民交易、331、陶瓦刷新三个规则合并进自动村民交易规则之中；交易索引现支持附魔书、陶瓦、331。
- 自动村民交易改为异步线程处理，转为异步模拟原版随机刻刷新模式，不再依赖此前的随机刻计算，更符合原版随机刷新概率。

#### 🖥️ 客户端与搜索
- 新增村民交易全局搜索功能，支持多语言搜索与通过配置自定义搜索关键词。尚未支持搜索特定等级的附魔书，仅能搜索满级附魔书；是否需要支持特定等级附魔书尚在评估。

#### 🔌 协议
- 新增客户端与服务端版本号握手通信，准备拆解服务端与客户端的版本差异兼容性框架。

#### 📚 文档
- 新增并整理整个项目的开发文档，归档项目框架以及各规则的实现细节，详情见 `doc` 目录下文档。

### 🐛 问题修复
- 修复村民自动刷新交易无法刷新交易的问题。
- 修复乐魂速度调整规则调整后无法立即生效、需要退出骑行状态并重新进入骑行状态才能生效的问题。
- 修复骑行在玩家头上退出游戏时未退出骑行状态，导致服务端每 tick 爆出巨量检查数据不一致日志的问题。
- 修复骑行在玩家头上退出游戏后重新进入游戏，骑行玩家无法见到被骑行者模型的问题。

### ⚡ 架构与性能优化

#### 🧵 异步与线程池
- 将查询操作放到异步线程处理。
- 优化线程池锁类型，将大面积的阻塞锁改为乐观锁。
- 线程池改为半阻塞式关闭和阶梯式自动扩容。
- 拆解总线程池，将 IO 线程池与业务线程池分离管理。

#### 📂 配置与 IO
- 优化配置命名。
- 重构配置管理生命周期，在游戏异常退出时执行一次强制写入配置。
- 重构 IO 写入模块并抽取到公共组件之中。
- 重构客户端与服务端配置信息同步接口，不影响兼容性。

#### 🧹 代码质量与性能
- 优化部分过度封装和迷惑写法。
- 移除部分反射注入导致的启动速度缓慢问题。
- 优化服务端与客户端潜在的内存泄漏问题。
